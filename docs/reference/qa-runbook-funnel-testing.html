Pay Close Attention To

Things that will look like bugs while you're testing but are actually known, current-state facts — plus the few things that are genuinely still open.

Stripe is in test modeMoney

Payment links are buy.stripe.com/test_.... A real card will be declined, not charged. Flip to live mode is a deliberate, separate step whenever you're ready — not automatic.

No client gets a real receptionist automaticallyProvisioning

A payment creates database rows and sends emails — it does not create a phone number or a Retell agent. Every real client needs manual setup by you before their line actually works. See Funnel B, step 5.

Rex, Nova, and Felix aren't universalCoverage

Rex (follow-up) and Nova (booking confirmation) are real and live only for roofing, HVAC, and plumbing. Felix (conflict check) is real and live only for legal. Every other vertical shows them as "Deploying" — that's accurate, not a display bug.

Scout has zero implementationSaaS only

Scout (competitor intelligence) exists only as marketing copy on the SaaS pages. No code runs behind it. Don't sell it as working.

Dental is waitlist-only

All dental agents are intentionally marked "Future." The dental page collects emails for later, nothing more.

(817) 635-0220 is a shared demo lineNever give this out

Ava answers as "ABC Company" and detects the vertical from context, ending every call with a spoken demo disclosure. It exists purely so any lead page can offer a live call. It is not, and should never become, a real client's number.

Your two logins behave differently on purpose

chris@369agenticsystems.com is the only admin — it lands on the internal Command Center. damozman@gmail.com is deliberately a normal client account for practicing the real customer experience — it lands on /client-dashboard and has a real (test-mode) subscription already on it.

Login codes expire in 60 minutes, single-use

If a code doesn't work, it's most likely expired or already used — request a new one rather than assuming something's broken.

One dev-only false alarm, already ruled out

If you ever run the site locally (npm run dev), the static lead pages 404 at their exact URL — that's a local dev-server quirk. Confirmed the live site returns 200 for all of them. Not a real bug, don't re-report it.
