7. Provisioning Bugs + Real Personalization

2026-07-12/13 — 7011368..270f593, all pushed

Started as a homepage sweep, turned into the first real end-to-end test of the per-client provisioning pipeline built back in Era "2026-07-11" (Priority #1) — and found it had never actually worked. Every fix below was verified by calling the real function or hitting the real API directly, not inferred from reading the code.

Production schema had silently drifted from schema.sqlFixed

calls.recording_url, six columns on agent_subscriptions (retell_agent_id, retell_phone_number, owner_phone, sms_phone_number, followup_method, preferred_area_code), and the entire client_questionnaires table existed in schema.sql and were referenced by shipped code, but the migration had never been run against production. Found via a column-by-column probe script, not by trusting the file. Real effect: every call_ended webhook was 500ing, and onboard-client.ts would throw after already creating a real Retell agent.

Every real customer's calls were being written to the shared demo accountFixed

call-received/route.ts hardcoded client_domain: 'demo.369agenticsystems.com' on every webhook, for every customer, always. Fixed by extracting agent_id from the real Retell payload (confirmed the exact field via a live test call) and looking it up in agent_subscriptions.retell_agent_id, with an explicit — not accidental — pass-through for the shared demo line. Verified against both the demo line and a real per-customer agent.

Agent provisioning 400'd on every real signupFixed

Cloning a template agent spread its own version metadata (version, response_engine.version) into the create payload — Retell rejects any version > 0 on a new agent. Two separate fields caused the identical error; found the second one by reproducing the exact API call locally instead of guessing from the error message a second time.

Phone number allocation hit an endpoint that doesn't existFixed

allocatePhoneNumber() hand-rolled a raw HTTPS POST to /v2/phone-numbers — 404, always. Real retell-sdk call is client.phoneNumber.create(). Also removed a silent fallback that wrote the shared demo line's own phone number into a real customer's database row when allocation failed — a real customer would have been told to call the demo line as if it were theirs.

Elite transcript search 500'd on every real requestFixed

request.nextUrl.searchParams triggered Next.js's static-optimization bailout; the route's own catch block swallowed the internal error and returned a generic 500. Added export const dynamic = 'force-dynamic'.

Real personalization built — every customer shared one LLM before thisBuilt, function-verified — not yet pipeline-verified

Cloning an agent only cloned the wrapper (name, phone, voice) — every customer on a vertical shared the exact same underlying LLM, same hardcoded "ABC Company" greeting, same generic prompt, no real personalization despite marketing copy implying otherwise. cloneAgentLlm() now gives each client their own LLM with their real business name baked in at provisioning. The questionnaire → knowledge-base sync was also found to be posting to a fabricated endpoint (404 on every call since it was built) — rewritten to merge questionnaire answers directly into that client's own prompt instead, idempotently. Both verified by running the real exported functions against the live Retell API (provision → insert fake data → sync twice → confirm no duplication → clean up) — not yet verified via an actual Stripe signup + real phone call, which is the standing gap before trusting this further.

A typo'd template agent ID for dentalFound, not yet fixed

RETELL_TEMPLATE_AGENT_DENTAL in .env.local/Vercel has an extra digit and doesn't match any real agent. Not urgent — dental isn't launched — but will break dental onboarding the instant it does.

Deploy-time messaging standardized to 24 hours everywhereFixed

Homepage, all 9 vertical cold-email pages, agent detail pages, the intake form, and the welcome email all previously said some mix of "72 hours" and "5–7 business days" (the exact contradiction Era 6 thought it had already resolved — it hadn't, fully). Standardized to 24 hours, backed by this era's confirmation that provisioning is synchronous within the webhook. Also dropped a "carrier forwarding" caveat that no longer applies — every customer gets a new dedicated number by policy, porting isn't part of the standard offering.

Test resource disciplineDone

Every debugging round in this era created real, billable Retell resources (agents, phone numbers) and Supabase rows. All of it — including 3 orphaned agents created by resend retries during debugging, with no dedup — was tracked and deleted by the end of the session. Verified zero remnants in both Retell and Supabase; the real demo line was never touched.

The core lesson of this era: multiple prior sessions' memory notes and delivery docs claimed this exact pipeline was "verified end-to-end" — those claims predated the schema even existing to support the writes. A schema file or a "DONE" doc sitting in the repo is not the same as the live system actually working. Everything in this era was confirmed by calling the real function or hitting the real API directly.

Chris asked if this already worked; it didn't. The webhook read a custom field no live Payment Link had configured — Stripe caps custom fields at 3, all 3 slots were already taken. Freed a slot by moving phone collection to Stripe's native phone_number_collection setting.

Agent never confirmed email/phone accuracy back to the callerFixed

Caught reviewing a real transcript: caller spelled their email letter-by-letter, agent read it back with a wrong letter (S for Z) and nobody caught it. None of the 9 vertical templates had any accuracy-check instruction. Added one to all 9 — spell email back, read phone digits back grouped. Applies to future signups via the template; not yet verified on a real call.

A real booking existed but the dashboard showed 0 AppointmentsFixed

Chris circled the stat and asked. Two independent bugs: call_ended unconditionally re-derived the outcome by keyword-matching Retell's summary and silently overwrote the real-time 'booked' stamp from book-appointment.ts; separately, available-slots formatted dates without a year, so the LLM had no grounding and guessed 2025 instead of 2026 on every booking, every vertical. Fixed both; corrected the existing bad row directly.

Elite live call transfer was completely broken, not just untestedFixed

Chris tried a real Elite call expecting a live transfer — the agent just recited the phone number as text. transfer_phone_number isn't a real field on the Retell SDK's Agent type (grepped to confirm) — the real mechanism is a transfer_call tool inside the LLM's general_tools. Fixed, patched directly onto Northside's live agent, and confirmed on a real call: agent said "connecting you to Chris," Chris's phone actually rang. Later upgraded from cold to warm transfer with a private handoff prompt after Chris asked whether the agent could brief him before connecting — confirmed on a second real call.
